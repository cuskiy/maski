# Internationalization

English is the source catalog and the fallback. The interface language is switchable. Message content is independent.

## Catalogs

- `src/i18n/en.ts` is the source; `src/i18n/zh-CN.ts` translates it.
- Every catalog key is typed. A missing key is a type/build error; a missing runtime entry falls back to English and never shows a key.
- One entry per sentence. Parameters are named; no string concatenation.
- Plural/number/date use `Intl.PluralRules`, `Intl.NumberFormat`, `Intl.DateTimeFormat`, and `Intl.RelativeTimeFormat`. Word search uses `Intl.Segmenter`.
- UI copy lives only in catalogs. A view calls `t("key", { ... })`.
- Static shell copy uses the same catalogs at build time.
- The app name is a parameter from `config.app.name`; catalogs do not duplicate the literal.
- No user-facing literal in a component, error branch, dialog, or notification.
- Test fixtures may contain non-English content when the behavior depends on it.

## Locales and paths

| Locale | Path | Role |
| --- | --- | --- |
| `en` | `/` | default, source, fallback |
| `zh-CN` | `/zh-CN/` | translation |

- `config.app.locales`, `defaultLocale`, and `fallbackLocale` are the only list.
- Every locale needs a catalog and a generated static shell; the build fails otherwise.
- The language switch changes the locale prefix (`/` or `/zh-CN/`), updates the catalog, `lang`, and `Intl` formatting without reload.
- Reloading loads the matching static shell.
- No runtime translation fetch. All catalogs are compiled into the bundle.
- The browser language does not auto-select in v1. English is the default; the user switches. Auto-redirect is an open decision (`AGENTS.md` 0.6 O1).

## Static shells

`scripts/shells.ts` generates one shell per locale:

- `<html lang>`, localized title, description, canonical.
- `hreflang` alternates and `x-default` to `/`.
- Localized boot text (brand/loading).
- Full-page `<noscript>`: brand, one `h1`, Matrix sync/E2EE needs JavaScript, enable/reload, static language link to the other shell.
- Manifest/theme colors from the config/paper tokens.
- The same external CSS/JS; shared hashed assets.

The shell template reads catalogs and config; the generated HTML is not hand-edited. No inline CSS/JS. The no-JS page is a real static page; it does not attempt to render the app.

## Language switch

- Auth page: compact switch in the corner; English or 简体中文.
- Settings > Account: Language row; English or 简体中文.
- The switch is available before login, so a wrong-language user can recover.
- No `System` option; auto-redirect is separate and open.
- The switch writes no server data; the path is the state.
- The no-JS overlay has a static language link, so language is recoverable without JS.

## Formatting

- Dates: `Intl.DateTimeFormat` with the resolved locale; relative today/yesterday via `Intl.RelativeTimeFormat`.
- Numbers/unread counts: `Intl.NumberFormat`; tabular numerals in CSS.
- Plurals: `Intl.PluralRules`; no hand-built plural logic.
- Search: `Intl.Segmenter` for word segmentation; NFKC, lowercase, diacritics.
- The `lang` attribute changes with the locale; assistive tech and fonts follow.
- Content language is not inferred; message text renders as written.

## Auto-redirect

Open. V1 default is English at `/` and a visible switch. If added:

- Must be a script for JS-enabled visitors; no-JS stays English.
- No `<meta http-equiv="refresh">`; it cannot choose by language.
- The script reads `navigator.languages`, matches `config.app.locales`, and replaces `/` with the matching shell only on the default path.
- It must not redirect when the user explicitly chose a language path.
- Add a test for no-JS and for a direct `/zh-CN/` visit.

## Build and audit

- The build checks every locale key exists in English; missing translations fall back.
- The shell audit checks `lang`, localized title/description, alternate links, boot, noscript, and the language link.
- The language switch test covers both paths, reload, `Intl` formatting, and a deep link with a room.
- Catalog size stays reasonable; no runtime fetch and no HTML from catalogs.
